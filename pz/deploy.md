# Общий порядок и этапы развертывания отказоустойчивой инфраструктуры

При развертывании отказоустойчивой инфраструктуры выделяется четыре этапа:

1) предварительная подготовка

2) непосредственное развертывание отказоустойчивой инфраструктуры

    2а) развертывание базовой инстраструктуры

    2б) развертывание сайта и сервисов

3) визуальный контроль инфраструктуры в Yandex Cloud Console и проверка доступности сайта и сервисов

---

Предварительная подготовка включает в себя:

- настройку АРМ администратора (создание сервисного аккаунта в Yandex Cloud, установка и настройка интерфейса командной строки Yandex Cloud (CLI), аутентификация в Yandex Cloud под сервисным аккаунтом)

- регистрацию доменного имени на стороннем сервисе [NoIp](https://www.noip.com/)

- создание TLS-сертификата в сервисе Yandex Certificate Manager (в проекте этот этап выполняется уже при развернутом сайте для обеспечения проверки прав на домен, но, так как выполняется вручную, то по формальному признаку вынесен на предварительную стадию)

---

Непосредственное развертывание отказоустойчивой инфраструктуры выполняется с помощью скрипта [start.sh](../start.sh), располагающегося в корневой директории репозитория и обеспечивающего автоматизированное последовательное выполнение этапов 2а и 2б

При необходимости можно последовательно выполнять этапы в ручном режиме:

- развертывание базовой инстраструктуры с помощью команды `terraform apply` выполняемой в папке /terraform

- развертывание сайта и сервисов c помощью команды `ansible-playbook -i ../terraform/hosts.ini site.yaml` выполняемой в папке /ansible

---

Визуальный контроль инфраструктуры в Yandex Cloud Console и проверка доступности сайта и сервисов содержит:

- визуальный просмотр в веб-браузере экранов задействованных сервисов Yandex Cloud (Compute Cloud, Managed Service for PostreSQL, Application Load Balancer, Virtual Private Cloud и др.)

- проверку доступности сайта по адресу https://fops41.freedynamicdns.net/

- проверку доступности сервисов Grafana и Kibana по ссылкам с использованием ip-адресов, отображаемых в Compute Cloud (также необходимо добавить к ссылке порты 3000 для Grafana и 5601 для Kibana)

- в сервисе Grafana проверку отображения информации на панелях дашбордов

- в сервисе Kibana проверку получения и отображения логов с nginx и остальных сервисов
